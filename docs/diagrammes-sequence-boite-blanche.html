مخططات سيناريوهات العلبة البيضاء (Scénarios Boîte Blanche)

إذا كانت مخططات العلبة السوداء تكتفي بالنظر للنظام من الخارج، فإن مخططات العلبة البيضاء (Diagrammes de Séquence de Conception / Boîte Blanche) تكشف **الهندسة المعمارية الداخلية لتطبيق الـ JEE الكلاسيكي (MVC 2)**. توضح هذه المخططات بدقة كيف تتعاون طبقات النظام: صفحات الـ JSP (Vue) ⟵ فلاتر الأمان (AuthFilter) ⟵ المتحكمات (Servlets) ⟵ طبقة المنطق (Métier) ⟵ طبقة البيانات (DAO & JDBC) ⟵ وصولاً إلى قاعدة البيانات (MySQL).

🎓 القيمة الأكاديمية الكبرى لهذه المخططات أمام الأستاذ (Validation du Module JEE) :
هذه هي المخططات المفضلة لدى أساتذة مادة JEE؛ لأنها تثبت احترامك التام لمعمارية MVC 2: فصل العرض (JSP) عن التحكم (Servlets) والبيانات (DAO/JDBC) مع استخدام نمط الـ Singleton في DBConnection والـ Sessions لإدارة الدخول الآمن.

1. دورة حياة المصادقة وتسجيل الدخول في MVC 2 (Login & AuthFilter)

يوضح هذا المخطط رحلة طلب تسجيل الدخول من نقرة المستخدم في login.jsp، مروراً بـ AuthFilter و LoginServlet، والتحقق عبر طبقة الـ Métier واستعلام PreparedStatement في قاعدة البيانات، وصولاً إلى إنشاء الـ HttpSession والتوجيه إلى /home:

User ⟶ login.jsp ⟶ AuthFilter ⟶ LoginServlet ⟶ MetierImpl ⟶ UserDaoImpl ⟶ DBConnection ⟶ MySQL
🔍 فتح الصورة بدقة كاملة
💻 كود PlantUML الأصلي لهذا المخطط 
@startuml
autonumber
skinparam style strictuml
skinparam defaultFontName Arial
skinparam sequenceMessageAlign center
skinparam roundcorner 8
skinparam BoxPadding 8
skinparam ParticipantPadding 10

actor "Utilisateur" as User #EFF6FF
boundary "login.jsp\\n(Vue)" as Vue #FEF9EE
control "AuthFilter\\n(Filtre Sécurité)" as Filter #F1F5F9
control "LoginServlet\\n(Contrôleur)" as Servlet #E0E7FF
entity "MetierImpl\\n(Couche Métier)" as Metier #ECFDF5
entity "UserDaoImpl\\n(DAO)" as DAO #FDF4FF
entity "DBConnection\\n(Singleton)" as DB #FEF2F2
database "MySQL\\n(lias_db)" as SQL #FFFBEB

User -> Vue : 1. Saisir email et password
Vue -> Filter : Requête POST /login
Filter -> Filter : doFilter() : Vérifier URL publique
Filter -> Servlet : chain.doFilter() -> doPost(request, response)

Servlet -> Servlet : getParameter("email"), getParameter("password")
Servlet -> Metier : authentifier(email, password)
Metier -> DAO : findByEmail(email)
DAO -> DB : getConnection()
DB --> DAO : Connection JDBC
DAO -> SQL : PreparedStatement: SELECT * FROM users WHERE email = ?
SQL --> DAO : ResultSet (données de l'utilisateur)

alt Succès : Mot de passe valide et Compte actif
    DAO --> Metier : return User bean
    Metier --> Servlet : return User authentifié
    Servlet -> Servlet : session.setAttribute("currentUser", user)
    Servlet -> Vue : response.sendRedirect(contextPath + "/home")
    Vue --> User : Afficher le tableau de bord (/home)
else Échec : Identifiants invalides ou Compte inactif
    Metier --> Servlet : return null
    Servlet -> Servlet : request.setAttribute("error", "Identifiants invalides")
    Servlet -> Vue : dispatcher.forward("/WEB-INF/views/login.jsp")
    Vue --> User : Réafficher formulaire avec message d'erreur
end
@enduml

DemandeDAO --> Servlet : return true

alt Si acceptation confirmée
    Servlet -> UserDAO : save(new User(nom, prenom, email, role="PERMANENT"))
    UserDAO -> SQL : INSERT INTO users (nom, prenom, email, role, actif) VALUES (?, ?, ?, ?, 1)
    SQL --> UserDAO : Generated Key (idUser)
    UserDAO --> Servlet : return User créé
    
    Servlet -> SQL : INSERT INTO affiliation_periods (member_id, date_debut, role) VALUES (?, NOW(), ?)
    SQL --> Servlet : Confirmation affiliation

    Servlet -> Servlet : simulerEnvoiEmail(email, motDePasseTemporaire)
end

Servlet -> Vue : response.sendRedirect("/adhesions?msg=decision_enregistree")
Vue --> Dir : Réafficher la liste actualisée avec badge "ACCEPTÉE"
@enduml

4. التحكيم وتوزيع العتاد مع فحص السجل السابق (MaterielServlet & Traçabilité) ⭐

تطبيق قاعدة دفتر التحملات (§14): يستعلم MaterielServlet عن سجل الاستفادة السابق للعضو (Qui a reçu quoi) قبل تنفيذ المصادقة والتحديث في جدول materiel_allocations:

🔍 فتح الصورة بدقة كاملة
💻 كود PlantUML الأصلي لهذا المخطط 
@startuml
autonumber
skinparam style strictuml
skinparam defaultFontName Arial
skinparam sequenceMessageAlign center
skinparam roundcorner 8

actor "Directeur" as Dir #FEF2F2
boundary "materiel.jsp\\n(Vue)" as Vue #FEF9EE
control "MaterielServlet\\n(Contrôleur)" as Servlet #E0E7FF
entity "DemandeDaoImpl\\n(DAO)" as DAO #FDF4FF
database "MySQL\\n(lias_db)" as SQL #FFFBEB

Dir -> Vue : Consulter les demandes et cliquer "Allouer"
Vue -> Servlet : POST /materiel (action="allouer", idDemande=5, idMembre=3)

Servlet -> DAO : findAttributionsPrecedentes(idMembre=3)
note right of DAO: Règle CDC §14: Vérifier "Qui a reçu quoi"
DAO -> SQL : SELECT * FROM materiel_allocations WHERE member_id = 3
SQL --> DAO : Historique des équipements déjà attribués
DAO --> Servlet : List (Historique d'attribution)

alt Attribution validée par la Direction
    Servlet -> DAO : updateStatutMateriel(5, "ATTRIBUE", date=NOW())
    DAO -> SQL : UPDATE materiels SET statut='ATTRIBUE', date_attribution=NOW() WHERE id=5
    SQL --> DAO : 1 row updated
    DAO --> Servlet : return true

    Servlet -> SQL : INSERT INTO materiel_allocations (materiel_id, member_id, date) VALUES (5, 3, NOW())
    SQL --> Servlet : Confirmation historisation

    Servlet -> Vue : response.sendRedirect("/materiel?msg=alloue_avec_succes")
    Vue --> Dir : Actualisation du tableau avec mise à jour du stock
else Refus ou quota dépassé
    Servlet -> Vue : response.sendRedirect("/materiel?msg=demande_rejetee")
    Vue --> Dir : Message d'information : quota atteint pour ce chercheur
end
@enduml

5. التوليد الآلي للتقرير السنوي وتصدير PDF (RapportServlet & Couche Métier) ⭐

يوضح كيف يقوم RapportServlet بتجميع المنشورات والأحداث لسنة معينة، واستدعاء دالة الحسابات في طبقة الـ Métier لحساب مؤشرات الأداء (KPIs) ومعدل التقدم (78%)، ثم إما إرسالها لـ rapport.jsp أو ضخها كملف PDF رسمي:

@startuml

entity "EvenementDao" as EvtDao #ECFDF5
entity "MetierImpl\\n(Calculs & KPIs)" as Metier #FEF9EE

Dir -> Vue : Sélectionner "2025-2026" et cliquer "Générer Rapport"
Vue -> Servlet : GET /rapport?annee=2025

Servlet -> PubDao : findPublicationsByYear(2025)
PubDao -> SQL : SELECT * FROM publications WHERE annee = 2025
SQL --> PubDao : List 2025
PubDao --> Servlet : return publicationsAnnee

Servlet -> EvtDao : findEvenementsByYear(2025)
EvtDao -> SQL : SELECT * FROM evenements WHERE date LIKE '2025%'
SQL --> EvtDao : List 2025
EvtDao --> Servlet : return evenementsAnnee

Servlet -> Metier : calculerIndicateursRapport(publicationsAnnee, evenementsAnnee)
Metier -> Metier : calculerTauxAvancement() -> 78%
Metier -> Metier : agregerParEquipe(IA: 42%, BigData: 28%...)
Metier --> Servlet : return BilanAnnuelBean

Servlet -> Servlet : request.setAttribute("bilan", BilanAnnuelBean)
Servlet -> Servlet : request.setAttribute("tauxProgression", 78)

alt Consultation à l'écran
    Servlet -> Vue : dispatcher.forward("/WEB-INF/views/rapport.jsp")
    Vue --> Dir : Affichage du rapport interactif (Graphiques, jauge SVG 78%, bilans)
else Exportation PDF officielle
    Dir -> Servlet : GET /rapport?action=export_pdf&annee=2025
    Servlet -> Servlet : GenerateurPDF.compilerRapport(BilanAnnuelBean)
    Servlet --> Dir : Flux binaire PDF (Content-Type: application/pdf)
end
@enduml
