3. دليل البناء خطوة بخطوة من الصفر المطلق في Eclipse 🛠️

إذا فتحت برنامج Eclipse على جهاز فارغ وأردت إعادة بناء هذا المشروع بنفسك وبحذافيره، فاتبع هذه الخطوات الدقيقة:

0

المتطلبات الأساسية (Les Pré-requis)

1. تثبيت Java JDK 21 (أو JDK 17 كحد أدنى).

2. تثبيت Eclipse IDE for Enterprise Java and Web Developers.

3. تنزيل خادم Apache Tomcat 10.1 (يدعم معيار Jakarta EE 10 و Servlet 6.0).

4. تنزيل مكتبة mysql-connector-j-8.x.jar للاتصال بقاعدة البيانات.

1

إنشاء المشروع في Eclipse (Création du Dynamic Web Project)

1. من القائمة العلوية اضغط: File > New > Dynamic Web Project.

2. في خانة Project name اكتب: gestion-du-laboratoire-LIAS.

3. في خانة Target runtime اختر: Apache Tomcat v10.1 (إذا لم تكن معرفة اضغط New Runtime وحدد مجلد Tomcat على جهازك).

4. في خانة Dynamic web module version اختر: 6.0.

5. اضغط Next ثم Next، وفي الخطوة الأخيرة قم بتفعيل الخيار الإلزامي: Generate web.xml deployment descriptor ثم اضغط Finish.

2

إضافة مكتبة MySQL في WEB-INF/lib

انسخ ملف mysql-connector-j-8.3.0.jar والصقه مباشرة داخل المجلد: src/main/webapp/WEB-INF/lib/.

ملاحظة مهمة للأستاذ: في مشاريع JEE الكلاسيكية، أي ملف JAR يوضع داخل WEB-INF/lib يتعرف عليه خادم Tomcat تلقائياً أثناء التشغيل دون الحاجة لإعدادات معقدة.

3

إنشاء قاعدة البيانات وجداولها في MySQL

1. افتح أداة MySQL Workbench أو التيرمينال.

2. افتح ملف schema.sql ونفذه بالكامل. سينشئ قاعدة lias_db و6 جداول أساسية مع إدخال بيانات تجريبية وحسابات الدخول الافتراضية.

4

إنشاء حزم الجافا (Java Packages)

داخل src/main/java، اضغط زر الفأرة الأيمن > New > Package وأنشئ الحزم التالية:

  • com.lias.beans : للنماذج وكائنات البيانات.
  • com.lias.dao : لواجهات وكلاسات الوصول لقاعدة البيانات.
  • com.lias.metier : لمنطق العمل وقواعد التحقق.
  • com.lias.web : للسيرفلتس والمتحكمات.
  • com.lias.filter : لفلاتر الأمان والتحقق من الجلسات.
5

برمجة طبقة النماذج (JavaBeans)

داخل حزمة com.lias.beans، أنشئ الكلاسات: User.java, Member.java, Publication.java, Evenement.java, DemandeAdhesion.java, Materiel.java.

احرص على تطبيق القواعد الذهبية: جعل الحقول private، إنشاء Constructor بدون بارامترات، دوال getters/setters، وتطبيق implements Serializable.

6

برمجة طبقة الاتصال وقواعد البيانات (DAO & JDBC)

1. إنشاء DBConnection.java بنمط Singleton للاتصال بـ MySQL عبر DriverManager.getConnection().

2. إنشاء الواجهات: IUserDao, IMemberDao, IPublicationDao, IEvenementDao, IDemandeDao.

3. إنشاء كلاسات التنفيذ المقابلة لها (مثل UserDaoImpl) واستخدام PreparedStatement لتفادي SQL Injection، مع وضع بيانات احتياطية (Fallback) لضمان اشتغال الموقع في أي ظرف.

7

برمجة طبقة المنطق (Couche Métier)

إنشاء الواجهة IMetier.java وكلاس التنفيذ MetierImpl.java التي تربط بين الـ Servlets والـ DAOs، وتنفذ قواعد التحقق من المدخلات وصحة البريد وكلمة المرور.

8

برمجة فلتر الأمان (AuthFilter)

إنشاء AuthFilter.java في com.lias.filter وتطبيق jakarta.servlet.Filter لفحص session.getAttribute("currentUser") وتوجيه الزوار غير المسجلين لصفحة تسجيل الدخول عند محاولة دخول لوحة التحكم.

9

برمجة السيرفلتس (Servlets)

إنشاء كلاسات ترث من HttpServlet لمعالجة مختلف الطلبات: LoginServlet, LogoutServlet, HomeServlet, MemberServlet, PublicationServlet, PublicServlet... مع دوال doGet و doPost.

10

تسجيل السيرفلتس والفلتر في web.xml

كتابة وسوم <servlet> و <servlet-mapping> لكل مسار، وربط الفلتر <filter-mapping> بالمسارات المحمية.

11

تصميم صفحات الـ JSP و CSS

إنشاء ملف css/style.css لتوحيد الألوان والخطوط، وإنشاء مجلد WEB-INF/views/ يضم navbar.jsp, footer.jsp وصفحات العرض.

12

التشغيل والاختبار داخل Eclipse

اضغط بزر الفأرة الأيمن على المشروع > Run As > Run on Server > اختر خادم Tomcat 10.1 > Finish.

سيفتح المشروع تلقائياً على الرابط: http://localhost:8080/gestion-du-laboratoire-LIAS/public.

4. دورة حياة الطلب ومخطط التدفق (Cycle d'une Requête HTTP) 🔄

لفهم ما يحدث خلف الكواليس عند كل نقرة للمستخدم، إليك المخطط التدفقي الكامل لمسار تسجيل الدخول مثلاً (De la requête HTTP jusqu'à la vue JSP) :

[1. Utilisateur] Remplir email/password sur /login & clic "Se connecter" │ ▼ [2. Requête HTTP POST] Envoi des données vers le serveur Tomcat (URL: /login) │ ▼ [3. AuthFilter] Vérifie si la ressource est publique ou protégée -> Laisse passer vers /login │ ▼ [4. LoginServlet.doPost()] ├── Récupère les paramètres: request.getParameter("email"), request.getParameter("password") ├── Appelle la couche Métier: metier.authentifier(email, password) │ │ │ ▼ │ [5. Métier / DAO] UserDaoImpl exécute SQL: │ SELECT * FROM users WHERE email = ? AND password = ? │ Retourne l'objet User (ou null si échec) │ │ │ ▼ ├── Si succès: │ ├── Enregistre l'utilisateur en session: session.setAttribute("currentUser", user) │ └── Redirection: response.sendRedirect(contextPath + "/home") └── Si échec: ├── Injecte message d'erreur: request.setAttribute("error", "Identifiants invalides") └── Réaffiche la vue: dispatcher.forward(request, response)

5. معمارية MVC 2 الكلاسيكية بالتفصيل

نمط MVC 2 (Model-View-Controller) هو المعيار المعتمد في تطبيقات الـ JEE المؤسساتية:

M

النموذج (Modèle) = Beans + DAO

يمثل البيانات وقواعد البيانات. في مشروعنا: كلاسات User, Member, Publication وطبقة الـ DAO عبر اتصال JDBC.

V

واجهة العرض (Vue) = JSP Pages

صفحات .jsp الموجودة في WEB-INF/views/. دورها فقط عرض البيانات عبر تعابير الـ EL مثل ${publications} بدون كتابة كود معالجة داخل الصفحة.

C

المتحكم (Contrôleur) = Servlets

سيرفلتس جافا تستقبل طلب المستخدم (HTTP Request)، تستدعي الـ DAO المناسب، تضع النتيجة في الـ Request، ثم تحول المستخدم للـ JSP المناسبة عبر forward().

6. طبقة النماذج (JavaBeans)

الـ JavaBean هو كلاس جافا قياسي يُستخدم كوعاء لحمل البيانات بين الطبقات المختلفة للتطبيق.

شروط الـ JavaBean القياسي التي طبقناها :

  1. يمتلك كونستركتور فارغ (Constructeur sans arguments).
  2. جميع حقوله خاصة (private) للتحقيق مبدأ التغليف (Encapsulation).
  3. يحتوي على دوال الوصول والتعديل القياسية (getters و setters).
  4. يطبق واجهة java.io.Serializable لتمكين حفظه في الـ Session أو نقله عبر الشبكة.
كود كلاس User.java الكامل
package com.lias.beans; import java.io.Serializable; public class User implements Serializable { private static final long serialVersionUID = 1L; private Long id; private String nom; private String prenom; private String email; private String password; private String role; // directeur, permanent, doctorant, admin, visiteur private boolean actif; public User() {} // Constructeur obligatoire sans paramètres public User(Long id, String nom, String prenom, String email, String password, String role, boolean actif) { this.id = id; this.nom = nom; this.prenom = prenom; this.email = email; this.password = password; this.role = role; this.actif = actif; } // Getters et Setters complets public Long getId() { return id; } public void setId(Long id) { this.id = id; } public String getNom() { return nom; } public void setNom(String nom) { this.nom = nom; } public String getPrenom() { return prenom; } public void setPrenom(String prenom) { this.prenom = prenom; } public String getEmail() { return email; } public void setEmail(String email) { this.email = email; } public String getPassword() { return password; } public void setPassword(String password) { this.password = password; } public String getRole() { return role; } public void setRole(String role) { this.role = role; } public boolean isActif() { return actif; } public void setActif(boolean actif) { this.actif = actif; } }

7. طبقة البيانات (DAO & JDBC)

نمط Data Access Object (DAO) يفصل كود استعلامات SQL تماماً عن باقي التطبيق.

أهم المفاهيم المطبقة في الـ DAO :

  • نمط السنجلتون (Singleton Pattern) في `DBConnection.java` : كونستركتور خاص (Private Constructor) ودالة getConnection() تضمن فتح اتصال واحد فقط مع MySQL لتفادي استهلاك موارد الخادم.
  • الحماية باستعمال `PreparedStatement` : استخدام علامة الاستفهام ? بدلاً من دمج النصوص المباشر، وهو ما يمنع هجمات حقن قواعد البيانات (SQL Injection) بنسبة 100%.
  • آلية الأمان البديلة (Fallback Data) : تم تزويد دوال الـ DAO بقائمة بيانات تجريبية افتراضية؛ فإذا لم تكن MySQL مشغلة، يظل الموقع يعمل بسلاسة دون أن ينهار أو يظهر شاشة خطأ أمام الأستاذ.
مثال: نمط Singleton في DBConnection.java
package com.lias.dao; import java.sql.Connection; import java.sql.DriverManager; public class DBConnection { private static Connection connection = null; private DBConnection() {} // Constructeur privé (Interdit l'instanciation directe) public static Connection getConnection() { if (connection == null) { try { Class.forName("com.mysql.cj.jdbc.Driver"); String url = "jdbc:mysql://localhost:3306/lias_db?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC"; connection = DriverManager.getConnection(url, "lias_user", "lias_password"); } catch (Exception e) { System.err.println("JDBC Connection Warning: Mode Fallback activé (" + e.getMessage() + ")"); } } return connection; } }

8. طبقة المنطق وقواعد العمل (Couche Métier)

تتمثل في الواجهة IMetier وتنفيذها MetierImpl.

دورها الأكاديمي : عزل "قواعد العمل" (Business Logic). على سبيل المثال: دالة authentifier(email, password) تتأكد أولاً من أن البريد ليس فارغاً، وتحوله إلى أحرف صغيرة (lowercase)، ثم تسأل الـ DAO للتحقق من صحة المستخدم وتأكد حسابه نشط. إذا طلب الأستاذ مستقبلاً تغيير شروط التسجيل، نعدل فقط في طبقة Métier دون المساس بالـ Servlets أو الـ DAOs.

9. طبقة المتحكمات (Servlets)

السيرفلت (Servlet) هي كلاس جافا ترث من HttpServlet وتتحكم في معالجة طلبات الويب.

دورة حياة السيرفلت (Cycle de vie du Servlet) :

  1. init() : تُستدعى مرة واحدة عند تحميل السيرفلت لأول مرة لتهيئة الموارد (مثل تهيئة كائن الـ DAO).
  2. service() : تستقبل الطلب وتوجهه إما إلى doGet() أو doPost().
  3. doGet(request, response) : لمعالجة طلبات الجلب وعرض الصفحات.
  4. doPost(request, response) : لمعالجة إرسال النماذج (مثل تسجيل الدخول أو إضافة مقال).
  5. destroy() : تُستدعى عند إيقاف السيرفر لتحرير الذاكرة.
مثال: سيرفلت تسجيل الدخول LoginServlet.java
package com.lias.web; import com.lias.beans.User; import com.lias.metier.IMetier; import com.lias.metier.MetierImpl; import jakarta.servlet.ServletException; import jakarta.servlet.http.*; import java.io.IOException; public class LoginServlet extends HttpServlet { private IMetier metier; @Override public void init() throws ServletException { metier = new MetierImpl(); } @Override protected void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException { request.getRequestDispatcher("/WEB-INF/views/login.jsp").forward(request, response); } @Override protected void doPost(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException { String email = request.getParameter("email"); String password = request.getParameter("password"); User user = metier.authentifier(email, password); if (user != null) { HttpSession session = request.getSession(); session.setAttribute("currentUser", user); response.sendRedirect(request.getContextPath() + "/home"); } else { request.setAttribute("error", "البريد الإلكتروني أو كلمة المرور غير صحيحة"); request.getRequestDispatcher("/WEB-INF/views/login.jsp").forward(request, response); } } }

10. سجل تهيئة المشروع (web.xml Deployment Descriptor)

ملف web.xml الموجود في src/main/webapp/WEB-INF/ هو عقل تطبيق الـ JEE الكلاسيكي. يقوم بالربط بين الروابط (URLs) والكلاسات البرمجية المسؤولة عنها:

مقتطف من web.xml
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee https://jakarta.ee/xml/ns/jakartaee/web-app_6_0.xsd" version="6.0"> <display-name>gestion-du-laboratoire-LIAS</display-name> <!-- فلتر الأمان --> <filter> <filter-name>AuthFilter</filter-name> <filter-class>com.lias.filter.AuthFilter</filter-class> </filter> <filter-mapping> <filter-name>AuthFilter</filter-name> <url-pattern>/home</url-pattern> <url-pattern>/rapport</url-pattern> </filter-mapping> <!-- سيرفلت تسجيل الدخول --> <servlet> <servlet-name>LoginServlet</servlet-name> <servlet-class>com.lias.web.LoginServlet</servlet-class> </servlet> <servlet-mapping> <servlet-name>LoginServlet</servlet-name> <url-pattern>/login</url-pattern> </servlet-mapping> <!-- صفحة البداية الافتراضية --> <welcome-file-list> <welcome-file>index.jsp</welcome-file> </welcome-file-list> </web-app>

11. الأمان والفلتر (AuthFilter) وإدارة الجلسات (HttpSession)

ما هو الـ Filter في JEE؟ هو كلاس تطبق واجهة jakarta.servlet.Filter، تعمل كـ "حارس أمن" يقف في المنتصف بين المتصفح والسيرفلت، ليفحص كل طلب قادم قبل السماح له بالمرور.

كيف يحمي كلاس `AuthFilter.java` مشروعنا؟

  1. يعترض أي طلب متوجه إلى الروابط الحساسة (مثل /home أو /rapport).
  2. يفحص الجلسة: session.getAttribute("currentUser") != null.
  3. إذا كان المستخدم مسجلاً، يستدعي chain.doFilter(req, res) ليسمح له بالمرور.
  4. إذا كان غير مسجل، يقوم فوراً بإعادة توجيهه: response.sendRedirect(contextPath + "/login?error=auth_requise").

12. طبقة العرض (Vues JSP) واعتماد نظام التصميم الأكاديمي (Design System) 🎨

صفحات JavaServer Pages (JSP) توجد داخل مجلد WEB-INF/views/.

سؤال ذكي للأستاذ: "لماذا وضعت ملفات الـ JSP داخل WEB-INF وليس مباشرة في webapp؟"
إجابتك : "لأن مجلد WEB-INF محمي أمنياً من خادم Tomcat؛ لا يمكن لأي مستخدم من الخارج كتابة رابط الصفحة مباشرة في المتصفح وتجاوز السيرفلت. صفحات JSP لا يمكن الوصول إليها إلا عن طريق السيرفلت عبر RequestDispatcher.forward()، وهو المعيار الصارم لأمان MVC."

كيف اعتمدنا الديزاين بالكامل وحولناه إلى معمارية JEE كلاسيكية؟

بناءً على ملفات التصميم الأصلية في مجلد design/ (الموقع العام Site Public LIAS.html، صفحة الدخول Login LIAS.html، والتطبيق الشامل LIAS-Application-standalone.html)، قمنا بتحويل كل صفحة إلى قالب JSP ديناميكي متصل ببيانات السيرفر مع توحيد الأنماط داخل src/main/webapp/css/style.css:

1

هوية بصرية مؤسساتية وأكاديمية رفيعة (Prestige Académique)

لوحة الألوان : تم استخدام لون كحلي داكن ملكي (--navy: #1B2F4A) يرمز للرصانة، مع خلفية ورق أرشيفي بيج دافئ (--bg: #F4EFE6) بنسيج نقطي خفيف، ولمسات ذهبية راقية (--accent-2: #B08838).

الخطوط المختارة : خط Spectral الكلاسيكي للترويسات والعناوين الأكاديمية الكبرى، وخط DM Sans للنصوص، وخط JetBrains Mono للتواريخ والمعايير الرقمية.

2

15. بنك الأسئلة والأجوبة النموذجية للمناقشة أمام الأستاذ 🎓

إليك أشهر الأسئلة التي يطرحها أساتذة الـ JEE مع الإجابة الدقيقة لتنال أعلى نقطة بإذن الله:

لماذا اخترت Jakarta EE 10 / Servlet 6.0 ولم تستخدم حزم javax.servlet القديمة؟
لأن خادم Apache Tomcat 10+ انتقل رسمياً من حزمة javax.* إلى jakarta.* بعد انتقال حقوق تطوير جافا للمؤسسات إلى مؤسسة Eclipse Foundation. استخدام jakarta.servlet.* هو المعيار الحديث والمستقبلي لجميع تطبيقات JEE.
ما الفرق بين doGet و doPost ومتى تستعمل كلاً منهما؟
doGet تُستعمل لجلب وعرض البيانات، وتظهر بارامتراتها في عنوان الـ URL (مناسبة للتنقل والبحث). بينما doPost تُستعمل لإرسال بيانات حساسة أو كبيرة (مثل بيانات تسجيل الدخول أو إنشاء منشور)، حيث تُرسل البيانات مشفرة داخل جسم الطلب (HTTP Body) ولا تظهر في الرابط.
ما الفرق بين sendRedirect() و RequestDispatcher.forward()؟
forward() يتم بالكامل داخل الخادم (Côté Serveur) دون أن يعلم المتصفح؛ يحتفظ بنفس كائن الـ Request وتظل البيانات المرفقة فيه محفوظة (وهو ما نستعمله لعرض الـ JSP). أما sendRedirect() فهو يرسل أمراً للمتصفح ليقوم بطلب جديد بعنوان جديد (Requête HTTP différente)، مما يغير الرابط في المتصفح (ونستعمله بعد نجاح Login أو Logout لتفادي تكرار إرسال الفورم عند التحديث).
كيف تضمن عدم حدوث تسريب في الذاكرة عند الاتصال بقاعدة البيانات؟
عبر تطبيق نمط Singleton في كلاس DBConnection لفتح اتصال واحد، واستعمال صيغة try-with-resources أو التأكد من إغلاق ResultSet و PreparedStatement بعد كل استعلام.
لماذا استخدمت PreparedStatement بدلاً من Statement العادية؟
لسببين جوهريين: الأمان لأنها تمنع هجمات حقن قواعد البيانات (SQL Injection) عن طريق تمرير المتغيرات كمعاملات منفصلة (?)، والأداء لأن محرك قاعدة البيانات يقوم بترجمة وتحسين خطة تنفيذ الاستعلام (Pre-compilation) مرة واحدة ويعيد استخدامها.
كيف قمت بتأمين الجلسة عند تسجيل الخروج (Logout)؟
داخل LogoutServlet نقوم باستدعاء session.invalidate() التي تدمر كائن الجلسة من ذاكرة السيرفر نهائياً وتلغي صلاحية الكوكيز، ثم نقوم بعمل sendRedirect لصفحة الدخول.
لو سألك الأستاذ: لماذا لم تستخدم Spring Boot أو Hibernate؟
لأن الهدف الأكاديمي الأساسي هو إتقان وفهم المعايير القياسية الصافية للجافا المؤسساتية (Core JEE Architecture)، ومعرفة كيف يعمل الـ Servlet Container والـ Session والـ JDBC من الصفر دون الاعتماد على مكتبات سحرية (Magic Frameworks) تحجب التفاصيل المنهجية عن الطالب.
