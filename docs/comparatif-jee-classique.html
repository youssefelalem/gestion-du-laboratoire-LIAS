المقارنة التفصيلية للنقاط الـ 7 بين النمطين

1

المعمارية العامة: النمط المترابط (Monolithique) مقابل النمط المفصول (Découplée SPA + REST)

Architecture Globale

في المشاريع الجامعية القديمة، يتولى خادم Tomcat كل شيء؛ بينما في هذا المشروع، تم فصل مسؤولية الواجهة (Client-side) عن المنطق الخلفي (Server-side API).

🏛️ في مشاريع JEE الكلاسيكية :
  • مشروع واحد موحد (Monolithe) داخل Eclipse.
  • كل نقرة على رابط أو إرسال نموذج (Form) يُعيد تحميل الصفحة كاملة (Rechargement complet de page).
  • خادم Tomcat يقوم برسم وتوليد الـ HTML على السيرفر (Server-Side Rendering - SSR).
🚀 في مشروع LIAS الحالي :
  • معمارية مفصولة حديثة (Monorepo: frontend/ + backend/).
  • تطبيق صفحة واحدة (Single Page Application - SPA) لا يُعيد تحميل الصفحة نهائياً.
  • الـ Backend (Java Tomcat) يتكفل حصراً بـ API REST وتوزيع بيانات JSON دون توليد صفحات HTML.
القيمة المضافة أمام اللجنة : سلاسة مذهلة في الاستخدام، استجابة فورية، ومواكبة تامة للمعايير المعتمدة في كبرى الشركات البرمجية.
2

تقنيات الواجهة الأمامية: صفحات JSP و JSTL مقابل React 18 و TypeScript

Frontend Tech Stack

الاستغناء عن السكربتات المضمنة في HTML وتعويضها بمكتبات المكونات الحديثة والمتحكم في حالتها (State Management).

🏛️ في مشاريع JEE الكلاسيكية :
  • صفحات .jsp مليئة بكود الجافا المباشر (Scriptlets: <% ... %>).
  • استخدام مكتبات JSTL مثل <c:forEach> و <c:if>.
  • كود JavaScript يدوي أو jQuery بسيط يصعب صيانته ويكثر فيه تكرار الأخطاء.
🚀 في مشروع LIAS الحالي :
  • React 18 المبني على المكونات المعيارية وإعادة الاستخدام (Components Reusability).
  • TypeScript 5 الذي يوفر الأمان الصارم للأنواع (Static Type Safety) ويمنع أخطاء التشغيل.
  • Vite 5 كمحرك بناء سريع يدعم التحديث الحي الفوري (Hot Module Replacement - HMR) في أجزاء من الثانية.
القيمة المضافة : الحماية من أخطاء الـ Runtime بفضل TypeScript، مع إمكانية استخدام مكونات جاهزة وأيقونات متقدمة مثل Lucide Icons.
3

التصميم وتجربة المستخدم: ملف CSS عشوائي مقابل نظام تصميم متكامل (Design System & Tailwind)

UI/UX & Styling

الانتقال من واجهات رمادية غير منسقة إلى نظام تصميم أكاديمي فاخر مستوحى من كبرى الدوريات العلمية.

🏛️ في مشاريع JEE الكلاسيكية :
  • ملف style.css كلاسيكي أو Bootstrap 3 قديم.
  • ألوان أساسية غير متناسقة (أزرق وأحمر وأخضر باهت).
  • غياب التوافق المتجاوب الحقيقي مع مختلف الشاشات والأجهزة اللوحية.
🚀 في مشروع LIAS الحالي :
  • Tailwind CSS 3 مع متغيرات تصميم موحدة (Tokens) في theme.css.
  • لوحة ألوان أكاديمية دقيقة (ورق كريمي #FAF8F5، كحلي بحري عميق #152B44، وذهب مؤسساتي #C5A880).
  • طباعة راقية معتمدة على خطوط Google Fonts الاحترافية (خط السيريف Spectral، و DM Sans، ومونو JetBrains Mono).
4

إدارة الأدوار والصلاحيات (RBAC) ومحاكي العرض الحي

RBAC & Security

في النمط القديم تحتاج لإنشاء حساب وتسجيل الدخول والخروج كل مرة؛ بينما في هذا المشروع تتوفر ميزة استعراض الأدوار الحية (Role Switcher).

🏛️ في مشاريع JEE الكلاسيكية :
  • الاعتماد فقط على HttpSession.getAttribute("role").
  • إخفاء الأزرار فقط عبر <c:if test="...">.
  • لتجربة دور المدير، يجب تسجيل الخروج ثم الدخول كمدير؛ ولتجربة الدكتورانت، يجب الخروج مرة أخرى.
🚀 في مشروع LIAS الحالي :
  • محرك صلاحيات ديناميكي في الواجهة (SessionContext) مبني على مصفوفة MODULE_ACCESS.
  • مبدل أدوار فوري (RoleToggle) أعلى الشاشة يتيح للجنة التحكيم تجربة صلاحيات 5 أدوار بنقرة واحدة.
  • ظهور علامة القفل (🔒) ديناميكياً على القوائم المحظورة لمنح إحساس بصري بأمان النظام.
  • تأمين السيرفر في الخلفية عبر فلتر الأمان AuthFilter لقطع أي طلب غير مرخص.
5

البيئة والتشغيل: التثبيت اليدوي المضني مقابل الحاويات الجاهزة (Docker Compose)

DevOps & Containerization

حل مشكلة "المشروع كان شغال عندي في لابتوبي لكنه لا يعمل في لابتوب الأستاذ" نهائياً عبر Docker.

🏛️ في مشاريع JEE الكلاسيكية :
  • تثبيت يدوي لـ JDK 21 و Apache Tomcat محلياً في الويندوز.
  • تثبيت XAMPP أو MySQL Server وتكوين منفذ 3306 يدوياً.
  • حتمية تصدير ملف WAR وضبط إعدادات السيرفر في Eclipse، وهو ما يفشل غالباً أثناء العرض.
🚀 في مشروع LIAS الحالي :
  • ملف docker-compose.yml موحد يجمع الخدمات الثلاث: (Frontend + Backend + MySQL).
  • أمر واحد يطلق كل شيء بضغطة زر: docker compose up --build.
  • يعمل في أي حاسوب (ويندوز، ماك، لينكس) دون الحاجة لتثبيت أي برامج وسيطة.
6

معيار الجافا: Java EE 8 (قديم) مقابل Jakarta EE 10 و Java 21 (حديث)

Java Specifications

اعتماد الإصدارات الحالية المستقرة طويلة الأمد والتحديث الجذري لمكتبات السيرفلت.

🏛️ في مشاريع JEE الكلاسيكية :
  • حزم قديمة تبدأ بـ javax.servlet.* (Java EE).
  • نسخ جافا قديمة (Java 8 أو Java 11) مع Tomcat 8 أو 9.
  • ملفات web.xml بالإصدار القديم 3.1 أو 4.0.
🚀 في مشروع LIAS الحالي :
  • حزم حديثة تبدأ بالمعيار الجديد jakarta.servlet.*.
  • الاعتماد على Java 21 LTS مع سيرفر Tomcat 10.1.
  • تكوين web.xml وفق أحدث معيار رسمي Servlet 6.0 / Jakarta EE 10.
7

منهجية التطوير: الارتباط الصلب بالقاعدة مقابل منهجية Mock-First / Contract-Driven

Development Methodology

في المشاريع التقليدية، إذا توقفت قاعدة بيانات MySQL ينهار المشروع بالكامل؛ أما في هذا المشروع فالنظام مصمم بمرونة عالية.

🏛️ في مشاريع JEE الكلاسيكية :
  • ارتباط كلي (Tight Coupling) بوجود قاعدة بيانات ممتلئة مسبقاً.
  • إذا حدث خطأ في استعلام SQL يتعطل مسار التطبيق وتظهر شاشة بيضاء أو خطأ 500.
🚀 في مشروع LIAS الحالي :
  • منهجية Contract-Driven: تم تحديد الأنواع (Types) والـ Endpoints مسبقاً، وتزويد النظام ببيانات محاكاة (Mock Data) غنية تعرض جميع الشاشات الـ 16 كاملة.
  • الـ Backend يحتوي على آلية Fallback ذكية في UserDaoImpl تضمن نجاح تسجيل الدخول حتى لو كانت MySQL متوقفة.

🎓 نصائح ذهبية لك أمام لجنة التحكيم (Soutenance) :

عند تقديم هذا المشروع أمام أستاذك أو لجنة المناقشة، ركّز على هذه النقاط لإبهارهم والتأكيد على تميز مشروعك:

  • بيّن أنك احترمت متطلبات الـ JEE : وضّح للجنة أنك بنيت هيكلية Eclipse المعيارية (JavaBeans, DAO, Métier, Servlets, Filtre d'authentification) ولم تهمل الأساس الأكاديمي المطلوب في مادة JEE.
  • اشرح سبب التطوير : أخبرهم أن مشاريع الشركات الحقيقية اليوم لا تستخدم JSP كواجهة، بل تفصل الـ Frontend بـ React لرفع الأداء وتترك الـ Backend كخادم API REST.
  • استعرض ميزة الـ Role Switcher : في العرض التقديمي، غيّر الأدوار بين (Directeur, Doctorant, Permanent, Visiteur) واشرح كيف تتغير الصلاحيات في رمشة عين؛ فهذه النقطة تعطي انطباعاً مبهراً عن نضج النظام.
  • أشر إلى الـ Docker : اذكر أن المشروع جاهز للنشر السحابي (Cloud-Ready) عبر Docker Compose بضغطة زر واحدة.
